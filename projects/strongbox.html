Strongbox

An audit platform that checks SAP journal entries against accounting controls and proves the records it checked were never altered.

Audit tests run on copies nobody can vouch for

Finance teams and auditors test journal entries for the same risks every close: the same person entering and approving an entry, postings dated in the past, large manual journals hitting sensitive accounts. The usual way is to export data from the ERP into spreadsheets and filter it by hand.

Once the data leaves the ERP, nobody can prove the rows being tested are the rows that were posted. Every exception then has to be traced back to its documents by hand before anyone can act on it.

Make every control result provable

I set out to build a product that runs these controls automatically on SAP data and backs every claim it makes. The data it checked has to be provably untouched, and every exception has to point to the exact records behind it.

A fingerprint for every record, and evidence for every finding

  • Every accepted record gets a SHA-256 fingerprint, and the fingerprints are linked into a chain. Verification rebuilds the whole chain, so any change, deletion or reordering shows up.
  • A library of 13 controls, each mapped to the audit standards it serves, with a remediation step and downloadable evidence down to the document number.
  • Every report run is frozen with its exact inputs: dataset, control versions, settings, and the code and container that produced it. Any result can be reproduced later.
  • Changes to controls and thresholds are versioned and need an independent approval before they go live, so no one can quietly loosen a check.

I built it as a full-stack product: a Python and Flask API on PostgreSQL, a React and TypeScript front end, and Docker for deployment to a cloud server. Browser tests walk through the complete workflow, from accepting a dataset to downloading a report.

Findings you can trace, and tampering you can't hide

On a synthetic SAP dataset of 1,726 journal entries, a single run flagged 9 failed controls. One of them found 31 entries that were entered and approved by the same person, each listed with its document number.

Then the real test. I changed one amount directly in the database, bypassing the application. The next verification failed and named the exact batch that had been altered.

$ python -m blackbox.cli tamper-demo
Tampered BSEG row for document 100000895 via direct SQL (amount changed, hash NOT updated)
Chain verification after tamper: fail -- Record hash mismatch in batch 20 (2000-2026-05/BSEG)

Strongbox is at v0.1 and runs on synthetic data. It has no customers yet, and its reports are marked test-only until it is validated with real auditors.
